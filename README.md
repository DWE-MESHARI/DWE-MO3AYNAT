# نظام إدارة المعاينات — دار وإعمار

موقع داخلي لشركة **دار وإعمار للتطوير العقاري** لإدارة مواعيد معاينة المشاريع العقارية، متابعة الحضور، وتنظيم بيانات العملاء.

بُني بـ HTML / CSS / JavaScript عادي (بدون أي إطار عمل أو أدوات بناء) — ملف يُفتح مباشرة في أي متصفح أو يُستضاف على أي استضافة ثابتة.

## المزايا

- **صفحة ضيوف عامة**: أي زائر (بدون تسجيل دخول) يرى تقويمًا لمن لديهم معاينات، بأسمائهم وأوقاتهم ووحداتهم فقط — بدون أي بيانات حساسة.
- **تسجيل دخول موظفين**: بريد إلكتروني وكلمة مرور (عبر Firebase Authentication عند ربطه، أو حسابات تجريبية قبل ذلك).
- **لوحة متابعة شاملة**: تحليلات لحظية، تقويم بألوان حسب كثافة المعاينات (أخضر → أحمر)، حركة أسبوعية، أداء كل مشروع.
- **إدارة مشاريع متعددة**، كل مشروع بلون مميز خاص به، مع صفحة تفصيلية لكل مشروع (تقويمها، كل الأشخاص، فلاتر الحضور، الدفعات).
- **استيراد بيانات من إكسل** — عند إنشاء مشروع جديد مباشرة، أو لإضافة دفعة جديدة لمشروع قائم، مع كشف الصفوف المكررة تلقائيًا.
- **تتبّع الحضور وإعادة الجدولة**: حضر / لم يحضر / إعادة جدولة مع سبب وسجل كامل لكل تغيير.
- **تقارير طباعة**: يومية (مرتّبة بالوقت)، أسبوعية، وشهرية — لكل مشروع.
- **تصدير كامل البيانات** كملف إكسل (نسخة احتياطية).
- **تذكير واتساب** بضغطة واحدة لكل عميل من بطاقة معاينته.
- **دعم Firebase اختياري**: يعمل بتخزين محلي بدون أي إعداد، ويتحول تلقائيًا لقاعدة بيانات Firebase الحقيقية عند تعبئة الإعدادات.

## التشغيل محليًا

لا حاجة لأي تثبيت. افتح `index.html` مباشرة في المتصفح، أو شغّل خادمًا محليًا بسيطًا (أفضل لتفادي بعض قيود المتصفح على الملفات المحلية):

```bash
# Python
python3 -m http.server 8000

# أو Node (npx)
npx serve .
```

ثم افتح `http://localhost:8000`.

## النشر

أي استضافة لملفات ثابتة تعمل مباشرة: **GitHub Pages**, Netlify, Vercel, Firebase Hosting، أو أي خادم عادي. فقط ارفع محتوى هذا المجلد كما هو.

### النشر على GitHub Pages
1. ارفع هذا المستودع إلى GitHub.
2. من إعدادات المستودع (Settings) → Pages → اختر الفرع (عادة `main`) والمجلد الرئيسي (`/root`).
3. احفظ — سيصبح الموقع متاحًا على رابط من نوع `https://<username>.github.io/<repo-name>/`.

## ربط Firebase (اختياري، لكن موصى به لبيانات حقيقية)

بدون إعداد، يعمل الموقع بتخزين محلي في متصفح كل زائر (كل شخص يرى بياناته فقط، لا مزامنة بين الأجهزة). لتفعيل قاعدة بيانات حقيقية تُزامن بين جميع الموظفين:

1. أنشئ مشروعًا على [console.firebase.google.com](https://console.firebase.google.com).
2. **Firestore Database** → Create database (ابدأ بوضع الاختبار Test mode).
3. **Authentication** → Get started → فعّل طريقة **Email/Password** → أضف حساب Users لكل موظف (بريد وكلمة مرور).
4. **Project settings** → **Your apps** → أضف تطبيق ويب (</>) وانسخ كائن `firebaseConfig`.
5. افتح `js/app.js`، ابحث عن `const FIREBASE_CONFIG = null;` بالقرب من بداية الملف، واستبدل `null` بالكائن الذي نسخته.
6. الصق قواعد الأمان التالية في Firestore → Rules:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /projects/{projectId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /viewings/{viewingId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
  }
}
```

> **ملاحظة أمان**: هذه القواعد تسمح بالقراءة للجميع (لأن صفحة الضيوف العامة تحتاجها) وتحصر الكتابة/التعديل بالموظفين المسجّلين فقط. لأن القراءة مفتوحة، أي شخص متمرّس تقنيًا يستطيع نظريًا قراءة كامل البيانات (بما فيها الجوال ورقم الهوية) عبر أدوات المطوّر حتى لو الواجهة لا تعرضها. إن كانت خصوصية بيانات العملاء حسّاسة جدًا، الحل الأدق هو دالة سحابية (Cloud Function) تُنشئ ملخصًا عامًا محدودًا لصفحة الضيوف بدل قراءة الجدول الكامل مباشرة.

## حسابات الدخول التجريبية (قبل ربط Firebase)

معرّفة داخل `js/app.js` ضمن `DEMO_EMPLOYEES`:

```js
const DEMO_EMPLOYEES = [
  { email: "employee@darwaemaar.com", password: "Dar2026*" },
];
```

عدّل أو أضف حسابات كما تريد. بعد ربط Firebase، هذه القائمة لا تُستخدم — يتحول الدخول تلقائيًا لحسابات Firebase الحقيقية.
